# Settings extension contract

`settings-inventory.json` enumerates every entry in the executable Python `SETTINGS` registry. Run `python tool/check_desktop_contracts.py --check` in CI; use `--write` after reviewing registry changes. Equality checks names, count, validation metadata and availability. All environment settings are explicitly unavailable in the desktop; planned screen placement does not imply backend support.

The implemented sample edits only collaboration `max_consultations` through `/v1/settings`. This JSON setting is separate from the environment registry. `SettingsPage` loads the service value, maintains a typed draft, disables invalid or unchanged saves, and calls `DesktopSession.updateConsultationLimit`. That operation rereads the latest document and preserves unrelated settings and profiles. Connection identity is checked before writing. Backend revision/CAS is unavailable, so simultaneous writers can still race. Apply timing is new sessions.

For a new feature, place typed draft logic in `features/<feature>/controllers` and widgets in `presentation`. Instantiate `SettingField<int>(source: 'service endpoint', applyTiming: 'new sessions', parse: int.tryParse, validate: (v) => v < 0 ? 'Must be nonnegative' : null)`. Load a baseline only after successful reads, call `edit` on input, show `error`, and enable save only when dirty and valid. Route writes through an identity-aware session operation, then reload the authoritative response. Never turn an unavailable registry entry into a writable control without a real API contract.

Fake story states to maintain: loading, loaded unchanged, valid dirty, invalid dirty, read failure with retry, save failure with draft retained, connection replacement during read/write, and demo save explicitly labelled as memory only. `settings_field_test.dart` is the small fake-free draft example; use the existing fake `OdessyApi` for page/session tests and assert unrelated JSON fields survive a real save/reload seam.

The reusable SettingsFormController<T> now owns loading, save/reload, loaded/dirty/error states and disposal suppression. SettingsPage only binds closures to DesktopSession and renders with ListenableBuilder. settings_form_test.dart covers pending load disposal, read failure, failed save draft retention and successful authoritative reload. Python tests/test_desktop_settings_inventory.py deliberately removes and adds entries; validation raises ValueError even under python -O.
