## Persistence semantics

* Path: `conversations.sqlite3` beside `ODESSY_CONFIG_FILE`, else `~/.config/odessy/`; tests always inject a temp path. POSIX files are created 0600; Windows inherits user directory ACLs. `usage-history.sqlite3` and telemetry stores are untouched.
* Schema `PRAGMA user_version = 1`; WAL (falls back if the filesystem refuses), `foreign_keys=ON`, 5 s busy timeout, one connection per operation, all writes serialized under one lock and each in `BEGIN IMMEDIATE`; success is reported only after `commit`.
* `append` is idempotent by `event_id`; the same id with a different payload/kind is a 409 conflict. Event timestamps come from the recorder, so original ordering/timestamps survive adoption.
* Limits: title 120 chars, event payload 256 KiB (413), export 2 MiB (413), search query 512 chars, snippet ≤ 400 chars, page sizes 1–100.
* A newer `user_version` → 503 `schema_too_new`; a corrupt file → 503 `corrupt`; neither is reset. A write failure (including an injected disk error) raises and leaves no row; tests assert nothing was acknowledged.
* Deliberately not stored: process handles, grants, tokens, live approvals, audio/capture, attachment contents.
