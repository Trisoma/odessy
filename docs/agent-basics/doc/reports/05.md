## B14 — workspace checkpoints: implemented

`src/odessy/application/checkpoints/` (`service.py`, `routes.py`, `__init__.py`).

**Mechanism — additive Git, never the user’s state.** Capture runs `read-tree --empty` in a *private
temporary index* (`GIT_INDEX_FILE`), `git add -- <captured paths>`, `write-tree`,
`commit-tree <tree> -p HEAD`, and pins the result with an owned ref
`refs/odessy/checkpoints/<ckpt_…>`. No `git add`/`reset`/`clean`/`checkout` ever runs against the
user’s index, branch or worktree; a test asserts HEAD, branch and staged paths are byte-identical
before and after creating a snapshot.

**Metadata** lives outside the workspace in
`<state_dir>/<sha256(workspace identity)>/checkpoints.json`: schema version, revision, per-checkpoint
`{id,label,created_at,revision,workspace_id,files,bytes}`, per-path `sha256`, and the unsupported
list. Atomic same-directory write (`mkstemp`+`fsync`+`os.replace`).

**Bounds (enforced, not aspirational):** 1000 files, 2 MiB per file, 10 MiB total, 20 retained
checkpoints per workspace, labels 1–120 printable characters.

**Exclusions:** `.git/**`, control characters, symlinks/non-files, anything the session policy marks
sensitive (`.env`, `*.key`, `*.pem`, `*secret*`, credentials, sensitive segments), and files outside
the authoritative root. Excluded paths are reported as `unsupported`, never silently captured —
therefore a restore cannot revert them either.

**Restore protocol** (`GET /preview`, then `POST /restore`):
1. `preview_hash` binds the *current content* of every captured path (not just status words), so a
   second edit with an unchanged `modified` status still invalidates the preview.
2. `expected_revision` must match the checkpoint revision (`409` otherwise).
3. Grant refused or unwired → `403`/`501`; nothing is written.
4. Binding and the plan are revalidated *after* authorization, immediately before the effect.
5. A mandatory **safety checkpoint** (`pre-restore …`) is taken first; its failure aborts the restore.
6. Only captured paths are rewritten, atomically per file. Untracked, unrelated, sensitive and
   unsupported files are untouched — asserted by test.
7. Response: `{version:1, checkpoint_id, safety_checkpoint_id, status:'restored'}`.

**Non-Git roots:** explicit `501` (“Checkpoints require a Git workspace root; this workspace is not a
Git repository”). No copy-based half-promise, no repository creation in the user’s folder. Bare repos
and workspaces that are not the repository root are also refused.

**Retention/delete:** pruning beyond 20 removes only our ref + metadata entry (tested); explicit
`delete` requires the same grant. Rollback is file-only: no claim about external effects, and no
terminal actions to undo (B13 absent).

**Authorization seam used (frozen):** constructor keyword dependencies only —
`inspector.binding(sid)` (existing `WorkspaceInspector`), `request_grant(sid, plan)` (broker), optional
`mode_revision(sid)`, and an owned `state_dir`. The module imports no `api.py`/`bootstrap` and creates
no competing session owner.
