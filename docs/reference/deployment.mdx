# Deployment

Odessy can run entirely on a laptop; a Jetson is optional. Set
`ODESSY_DEPLOYMENT=single` to run the model, Python runtime, and Node tools on
one computer. The CLI starts Node on loopback for the duration of the run.
With Node installed, the model has 13 tools, including files, search, Git,
calculator, time, and `terminal.run` on this computer.

Without the Node dependencies, only `time.now`, `calculator.eval`, and the Python
`terminal.run` are mounted and advertised. Model tool schemas and repair prompts use
the same available set. The Python `terminal.run` selects bwrap, landlock, seatbelt or
windows-acl per call where the host has one. windows-acl needs the Node tool server
built (it reuses its runner), so without Node on Windows commands run unconfined,
results report `enforcement: "none"`, Odessy says so at start, and
`ODESSY_ISOLATION=required` refuses them. Run `python -m odessy doctor` for setup
steps; the sandbox itself is described in `docs/reference/sandbox.mdx`.

Set `ODESSY_DEPLOYMENT=split` for the Jetson/laptop layout. Configure
`ODESSY_TOOL_SERVER_URL` (or `ODESSY_MCP_SERVER_URLS`) for the remote Node server.
Here `terminal.run` runs locally (on the Jetson, under bwrap when it is installed and
works) and `laptop.terminal.run` runs on the remote laptop.
When deployment is unset, a configured remote URL selects split; otherwise single
is the default.

For authenticated split execution, set `ODESSY_PAIRED_HOST=<enrolled-alias>` and,
if needed, `ODESSY_LINK_BIN=<path-to-odessy-link>`. This selects split mode and
replaces the raw remote URL. Explicit single mode or simultaneous remote-URL
configuration is rejected; an unavailable paired host never falls back to a raw
URL. Remote commands retain the name `laptop.terminal.run`. Enrollment and host-local
workspace/capability grants are separate steps; see [host pairing](host-pairing.mdx).

`ODESSY_LOCAL_OS` overrides local OS detection. `ODESSY_LAPTOP_OS` describes the
remote laptop in split mode. Both accept `windows`, `linux`, or `macos`.
Put comments on separate lines in the env file; inline comments are read as values.

This deployment change does not add peripheral drivers. Peripheral access still
depends on the available tools, OS support, permissions, and policy checks.

See the [setup guide](../../README.md) and [current limitations](current-limitations.mdx).
