---
title: Tool concurrency
---

Odessy v0.4.0 development supports native tool batches from cloud, Ollama, and LFM
adapters. A completed assistant response is required before tools can start.
Text-JSON fallbacks still request one tool at a time.

Set `ODESSY_TOOL_CONCURRENCY=2` to allow up to two eligible tools to overlap.
The default is `1` (sequential), and accepted values are integers from 1 through 8.
A native batch is preserved even at 1; every valid call runs in model order.
Each response permits at most 16 calls, and a turn permits 64 dispatched calls.

Only time, calculator, filesystem read/list, and project find/grep are candidates.
Shell commands, writes, log append, git operations, device tools, confirmation,
escalation, and all third-party MCP calls remain exclusive ordering barriers.
Trust and read-only annotations do not grant concurrency to external tools.
The model cannot grant authorization or mark its own calls safe to overlap.

Each call passes schema, policy, execution-target, and applicable isolation checks.
A denial or declined approval stops the remaining batch without a model retry.
Ordinary execution errors are returned as observations alongside sibling results.
Dispatch may complete out of order; model observations are committed in call order.
Barriers do not provide snapshots against changes made by other applications.

A stop launches nothing further and drains started calls for up to 30 seconds.
After that, client waits are cancelled. A remote server may still be processing a
request: an unknown-completion result says so and is never automatically retried.
Cancellation of synchronous model generation retains the adapter's existing limits.

The singular result fields still describe the last completed call. Python callers
can inspect `tool_observations` for the full ordered history and pass `stop_event`
to `run_turn` for cooperative stopping. Evaluation metadata records concurrency
and call limits; historical result artifacts are unchanged. Hardware speedups
and real Jetson behavior have not been validated by this implementation.
