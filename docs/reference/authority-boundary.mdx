Odessy v0.3.0 uses a local single-user command-line authority model.
The architecture is intentionally small, but the authority split is strict.

## Required Flow

```text
MODEL
  -> structured tool proposal
  -> Python Odessy Runtime
     -> schema validation
     -> policy
     -> execution target authorization
     -> workspace authority
     -> process authority
     -> isolation requirement and escalation
     -> confirmation when required
  -> MCP client
  -> Node MCP tool server
  -> tool handler
  -> execution environment
  -> structured observation
  -> Python runtime
  -> MODEL
```

## Non-Negotiable Rules

| Rule | Meaning |
|---|---|
| The model is not an authority | FakeModel, LFM2.5, or Gemma can propose, but cannot approve or execute. |
| MCP is not an authority | MCP is the protocol for `tools/list` and `tools/call`. |
| Node is not an authority | Node executes bounded tool handlers and performs defense-in-depth checks. |
| Python is the authority | Python owns validation, policy, workspace checks, process checks, and confirmation. |
| DENY means no execution | A denied request must not reach `tools/call`. |
| CONFIRM means human approval | The model cannot approve its own action. |
| Only authorized targets execute | A server must be explicitly marked an `ExecutionTarget` before any tool call reaches it. Holding one *is* the authorization; there is no default target set. |
| Requesting a wider mode is not self-granting | A denied `danger-full-access` request does not fall back to a wider mode, and can never satisfy a `required` isolation requirement. |

## Current Tool Surface

v0.3.0 keeps the v0.1.0 command-line scope:

```text
time.now
calculator.eval
terminal.run
filesystem.read
filesystem.list
project.find
project.grep
git.status
git.diff
git.changed_files
git.log
```

Voice integration arrived in v0.2.0 and remains part of the interface. GUI automation, robotics, and background autonomy remain outside the current scope.

## Defense In Depth

| Layer | Responsibility |
|---|---|
| Python runtime | Authoritative policy, workspace authority, process authority, confirmation. |
| MCP | Tool protocol and structured result transport. |
| Node tool server | Read-only tool handlers, schema validation, path guard defense in depth. |
| OS/process layer | cwd, sanitized environment, timeout, stdout/stderr bounds, process cleanup. |

## Authority Verification

The adversarial tests cover:

- relative and absolute inside paths;
- outside paths;
- sibling-prefix paths;
- symlink escape where supported;
- non-existent safe targets;
- sensitive filenames and directories;
- background and detached terminal attempts;
- sanitized environment behavior;
- stdout bounds;
- timeout handling;
- no-MCP-on-deny behavior.

## Development: human interaction grants

Offline implementation and independent review completed October 22, 2026 on
`feat/voice-user-interaction` through `3412025`; the feature is not yet merged or
released. Real microphone, Jetson and packaged-device qualification remain pending.

Voice approval is an intent signal, not identity authentication. A known spoken
phrase is not a replay-resistant authenticator; no speaker-recognition or NIST
assurance claim is made. See [NIST replay resistance](https://pages.nist.gov/800-63-4/sp800-63b.html#replay).
High-risk actions and all sandbox expansion require keyboard or authenticated UI.
Policy denials remain absolute. The model supplies neither risk nor channel identity.

The authoritative approval description comes from the validated operation, host,
canonical local targets, exact shell command and permission scopes. A model's
justification is separately attributed. This avoids using a generated explanation
as the authoritative operation description; see [OWASP HITL dialog forging](https://github.com/OWASP/www-community/blob/master/pages/attacks/lies-in-the-loop.md).

One-use grants bind the controller's request/turn, stable call identity, canonical
arguments, target identity, scopes and relevant policy/configuration state.
Exact command bytes are bound; display escapes controls and redacts secrets.
Local paths use existing workspace authority and are resolved again before
dispatch; foreign-host paths retain that host's existing validation rules.
Changed arguments, target, scopes, policy or local symlink target require a new
authorization decision. Grants are checked again after opening the transport.
Pre-dispatch argument comparison preserves JSON value types, including nested
values such as `1` versus `true`. Coding-job adapter identity is checked again
after awaited patch-worktree creation, immediately before command construction.

Ordinary confirmation and sandbox expansion share a combined request, with the
strongest required channel. Both authority and sandbox validation still run and
retain their audit/log records. A grant covers only its listed scopes and one
dispatch. It cannot weaken child-agent permissions or host authorization.

`user.ask` answers are attributed human information. They never authorize tools,
change policy or become a higher-priority instruction. Trusted voice, terminal
and authenticated HTTP adapters assign resolving channels. Model text, synthesized
speech and tool output are never accepted as authorization.
