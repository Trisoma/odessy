# Odessy v0.3.0 release notes

Release preparation: October 19, 2026. Publishing, tagging, and merging to `main`
remain maintainer actions; this document does not announce a published release.

## Changes since v0.2.0

- Host-dependent execution isolation with explicit enforcement reports. Windows
  confinement is partial; Jetson confinement depends on available host backends.
- Single-machine deployment: a laptop can run the model, runtime, and local Node
  tool server. The Jetson/laptop split deployment remains supported.
- Optional cloud backends, including DeepSeek reasoning effort and preservation of
  reasoning content across tool turns, bounded retries, and tool-result limits.
- Failed tools become observations the model can recover from. Every subsequent
  action remains subject to validation and authorization.
- Configurable generation/context limits, stream and attempt budgets, and separate
  timeout outcomes. Stream budgets are checked between lines, not hard HTTP deadlines.
- Evaluation provenance notes, visible abort details, and rates over all recorded
  attempts. The suite now has 56 cases, including 18 hard cases; three repeats give
  168 attempts. Keyword routing and the `--routing` option have been removed.
- Cloud turns default to 8 model calls; local turns default to 4.

## Release-preparation fixes

PowerShell expressions in parentheses or braces now require confirmation rather
than inheriting the read-only classification of a leading listing command. This is
conservative pattern matching, not a complete shell parser.

Workspace authority rejects resolved paths outside the workspace before checking
their existence, and converts filesystem errors during path checks into authority
errors. An inaccessible outside UNC path therefore produces a policy denial rather
than an uncaught `PermissionError`.

## Verification boundaries

Local Windows verification on October 19:

- Full Python suite: **817 passed, 3 skipped**. A final eval-version regression
  added during that run was separately verified with **74 eval tests passing**.
- Node suite: **173 passed, 1 skipped**; TypeScript typecheck and build passed.
- Laptop-only fake-model smoke: automatic local Node startup listed the workspace.
- Split smoke: a Linux-controller prompt and real loopback Node executor read
  `README.md` through MCP. This simulates wiring, not a second physical computer.
- Runtime and package source versions both equal `0.3.0`; all 56 cases load.
- Editable installation was attempted but the local build environment lacks
  `wheel` (`invalid command 'bdist_wheel'`). An installed-package smoke remains pending.

The first restricted Python run had two process-execution failures; rerunning with
process permissions passed the full suite. Node tests likewise required child-process
permission. The passing results above are from those permitted runs.

Jetson hardware is unavailable for this preparation. Local split-deployment tests
can check wiring and contracts, but cannot establish Linux/aarch64 inference,
audio, memory usage, or host confinement. No model evaluation was rerun, as requested.

The staged voice pipeline retains its documented limitations, including blank-audio
handling. There is no production authentication layer for exposed MCP endpoints,
and cloud redaction is best effort. See [current limitations](../reference/current-limitations.mdx).
