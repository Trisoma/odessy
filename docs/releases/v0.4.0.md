## Extra feature: automatic model selection

Merged into `develop` via PR #19 (`ea2b973`), unreleased and opt-in:
`--model-backend auto` uses text-only Gemma for narrow greetings and text
transformations, and a configured local capable model for uncertain/tool requests.
Cloud fallback requires explicit enablement and never follows tool dispatch.
Diagnostics retain routing decisions and cumulative generation costs. Jetson
latency and memory qualification remain pending; see
[automatic model selection](../reference/model-selection.mdx).

October 20 user-reported Jetson smoke tests returned answers for greeting,
rewrite, and time text requests; auto wake listening reached transcription,
thinking, and speaking. This does not verify the selected routes or tool use.
LFM appearing after spoken `Hi` is an unresolved observation requiring the actual
transcript, history, and escalation diagnostics. The Q8/15-layer test profile and
VAD correction (now included in the repository adapter) are recorded in the [Jetson guide](../jetson-wake-testing.md);
neither stable memory headroom nor a routing speedup has been established.

## Cloud cost and usage

**In development, unreleased.** Claude requests mark the tools and system prompt
cacheable; cached input tokens are read from every provider's usage and recorded in
turn diagnostics and eval attempts. Each cloud turn prints its tokens, and an
estimated cost when prices are configured (none are built in). A per-run token or
cost budget stops further cloud requests once reached. See
[cloud models](../reference/cloud-models.mdx#cost-and-usage).

## Evaluation: third-party servers, conversation, batches

**In development, unreleased.** Three categories (24 cases) cover v0.4.0 features:
`external` (simulated third-party servers through the real policy), `conversation`
(history passed as the voice session passes it), and `batch` (independent reads,
whether proposed together reported). Reports add confirmations per attempt. Written
and checked with scripted reference behaviours; no model results yet. See
`evals/README.md`.

## Extra feature: fewer, clearer confirmations

**Merged via PR #17 (`03771ab`), with PR #18 (`b86aea9`) batch follow-ups; unreleased.** More read-only commands run unasked (file readers
limited to the workspace, read-only git, program lookup, `--version`). Installers are
rated high risk. The terminal prompt now has two tiers: high risk needs a typed `yes`,
and other commands and third-party tools can be allowed for the rest of the run with
`a` (in memory only). `filesystem.write` shows a diff. Commands can be approved in
advance per workspace in `commands.toml` (still `workspace-write` mode), and several
calls proposed together are confirmed with one question. See `policy/README.md`.

Preapproval parsing rejects eval prefixes and incomplete task runners. Entries
apply only to local `terminal.run`, not split-mode `laptop.terminal.run`; `doctor`
reports that scope. See [Jetson wake testing](../jetson-wake-testing.md) for the
remaining wake setup and hardware acceptance procedure. The keyword download
alone does not supply openWakeWord's auxiliary detector models.

## Extra feature: third-party MCP servers

**Merged into `develop` on October 19, 2026 via PR #11 (`0f0e191`), unreleased.**
This extends the original v0.4.0 roadmap with opt-in tools from HTTP and stdio MCP
servers listed in `~/.config/odessy/servers.toml` or `ODESSY_SERVERS_FILE`.
Without a servers file, the tool surface is unchanged.

Tools are discovered once at startup and namespaced as `<server>.<tool>`.
Admission checks constrain names and input schemas; each call is validated
against the server's JSON Schema before execution and subject to policy,
confirmation, and explicit execution-target authorization. Configuration controls
trust and per-tool overrides; declared `workspace_paths` are checked even with
an allow override. Limits are 16 external tools for local models and 64 for cloud.

Listing a stdio server launches its program, including during startup discovery.
HTTP calls send arguments to the configured endpoint. Odessy's command sandbox
does not automatically confine third-party server programs or their side effects.
Server descriptions, schemas, annotations, and results remain third-party input.

Follow-ups, implemented in development after PR #11 (unreleased): direct
`jsonschema` dependency declaration; refusal of server and tool names that do not
survive the cloud adapters' `.`/`__` encoding; one kept session per stdio server;
`doctor` checks; and an audit log of third-party calls recording argument hashes,
not values. Evaluation runs do not discover user-configured external servers. See [configuration and decision rules](../reference/external-servers.mdx).

Other unfinished proposals in standalone planning files also move to the v0.4.0
cycle, subject to their stated prerequisites. They are not v0.3.0 release blockers.
Historical benchmark results and earlier release records retain their original versions.
