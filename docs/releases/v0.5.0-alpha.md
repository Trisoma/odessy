# v0.5.0-alpha — Developer Preview

[Public prerelease](https://github.com/Trisoma/odessy/releases/tag/v0.5.0-alpha) · November 19, 2026 · [Windows x64 installer](https://github.com/Trisoma/odessy/releases/download/v0.5.0-alpha/Odessy-v0.5.0-alpha-windows-x64-setup.exe)

The installer was built from `6f96e71`. It predates the OpenTelemetry 1.45.2,
`@hono/node-server` 2.1.6 and audio error-disclosure fixes in `08efca9`.
[Run from source](../getting-started.md) for those fixes. Updating the source
locks does not update an existing EXE or installation.

The unsigned installer offers Piper or Kokoro and a separate wake-model choice.
Use the [manual](../GOLDEN_PATH.md#1-install-and-open-odessy) for setup. The
[verification record](../verification/windows-piper-installer-2026-11-18.md)
identifies the file by checksum and records the checks and remaining gates.

This preview consolidates the production desktop, durable conversation history,
Custom continuation and access modes, explicit memory, local document retrieval,
conditional local PTY support, checkpoints, setup, read-only device monitoring and
separately authorized Custom SSH commands.
See the [current capability matrix](../current-status.md) for engine/platform differences.

## Version naming

- Public preview and Git tag: `v0.5.0-alpha`.
- This candidate's embedded Python distribution version: `0.5.0.dev0`.
- This candidate's embedded Flutter version: `0.5.0+1`.

The public alpha label does not imply that the embedded development versions were
bumped. Identify this candidate by its application commit and installer SHA-256
in the receipt above; embedded version strings alone cannot distinguish these
preview rebuilds. A future aligned version bump would use Python `0.5.0a0`
(PEP 440) and Flutter `0.5.0-alpha+<build-number>`, with a new build and receipt.
Historical version names and measured artifacts keep their original identity.

## Before the next installer build

At the v0.5.0-alpha source snapshot, Windows checkpoint restoration was disabled;
that is a historical property of that build, not of later commits. For a new
installer build, restoration uses handle-anchored replacement — verify the candidate
bundles that implementation (see [release verification](../release-verification.md))
rather than the old restriction, and retain creation/list/preview. Qualify the exact
merged-source package and record its hashes. Verify isolated install/update and
profile preservation; separate fixture credentials from a real OS vault. Keep
unsupported engines/platforms/capabilities visibly unavailable.

The preview seeks developer collaborators who can run a disposable-workspace path,
report reproducible problems and take a [scoped GitHub issue](https://github.com/Trisoma/odessy/issues) through review. It is not beta readiness, full sandboxing, broad hardware
support or a promise that every screenshot represents an available capability.
