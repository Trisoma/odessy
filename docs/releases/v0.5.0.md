# Odessy v0.5.0 planning

Planning decision: October 22, 2026. **Not released; scope is provisional.**

## Desktop application and documentation

Implementation plan: [Flutter desktop UI](../superpowers/plans/2026-10-22-flutter-desktop-ui.md),
using the supplied CC Switch-style device/settings layout and a focused conversation
view. It includes complete feature/configuration coverage, backend API gaps,
role-aware host management, mocked development and platform acceptance gates.

Confirmed direction, October 22: development may start now; delivery targets
v0.5.0. Odessy will have a desktop application, not a browser-based product UI.

- **Desktop:** Flutter + Dart, targeting Windows, macOS and Linux. Platform builds,
  native integrations, signing/packaging and acceptance require separate checks.
- **Documentation:** publish the static documentation on GitHub Pages (`github.io`)
  for v0.5.0. This is documentation hosting, not an application backend. Deployment
  is planned; no site has been published by this decision.
- **Existing services:** retain Python orchestration, model routing and voice, plus
  the TypeScript MCP execution host. The desktop client should initially reuse the
  authenticated session API/events and existing approval boundaries.
- **Native integration proposal:** use Rust for host connectivity, lifecycle or OS
  integration where needed, extending `odessy-link` when appropriate. Use C++ for
  specific native libraries/hardware bindings that require it. A general C++/Rust
  backend rewrite or mandatory extra bridge is not approved by this roadmap;
  choose concrete boundaries before implementation.

Flutter is the selected desktop direction; implementation and cross-platform
qualification are not complete. See [Flutter desktop support](https://docs.flutter.dev/platform-integration/desktop).

## Custom Odessy wake word

Deferred from v0.4.0 by decision on October 23: train or obtain a compatible
detector for **Odessy**, then qualify pronunciation, misses and false activations.
v0.4.0 retains **Hey Jarvis**. Review training data, synthetic-speech generators,
feature-extractor and final model licenses before distributing new weights; a
custom model is not automatically unrestricted. See the
[license inventory](../reference/third-party-licenses.md).

## Windows installation wizard

Deferred from v0.4.0. Work on `chenyang/install-wizard` is paused, with the current
prototype preserved for later iteration. Functionality is incomplete, and the
interface and icon need further work. The latest dark six-stage design is an
intermediate design, not the accepted final installation experience.

Before calling this ready:

- Agree on and complete the installation feature scope. Voice dependency setup,
  model migration, cloud account configuration, and split deployment are currently
  outside the prototype; decide which belong in v0.5.0 rather than assuming support.
- Finalize the interface, branding, and icon.
- Rebuild the standalone EXE and obtain passing Windows CI on the delivered revision.
- Perform clean-machine installation and packaged-device acceptance, including
  failure, cancellation, resume, maintenance, and uninstall checks.

`installation_ready` remains false. No release date or completed hardware
qualification is claimed. See the [installer documentation](../../installer/README.md)
for the prototype's current capabilities and limits.
